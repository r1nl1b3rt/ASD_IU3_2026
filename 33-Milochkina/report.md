## Задача 1. Максимум и минимум

### Идея решения

Входные числа сохраняются в целочисленном массиве.
Первый элемент принимается за начальные минимум и максимум, а остальные элементы последовательно сравниваются с ним.
При нахождении меньшего или большего значения соответствующая
переменная обновляется.

Поиск реализован в отдельном методе findMinMax.
Вывод: минимум и максимум через пробел.

### Анализ сложности

Пусть n — количество элементов массива.

Ввод содержит n итераций.
Поиск содержит n - 1 итераций, на каждой выполняется
не более двух сравнений и двух присваиваний.

Время работы: O(n), т.к. количество действий
растёт линейно с количеством элементов.

Память всей программы: O(n) для хранения входного массива.
Дополнительная память метода поиска: O(1), поскольку
количество его переменных и размер результата не зависят от n.

и завершает работу. Если совпадений нет, возвращает -1.

позиции: проверяются все n элементов, время поиска — O(n).

Ввод массива занимает O(n), поэтому время всей программы — O(n).

Дополнительная память метода поиска — O(1).
Память всей программы — O(n) для хранения массива.

## Задача 4. Все индексы элемента

### Идея решения

Массив просматривается слева направо.
При совпадении элемента с искомым числом его индекс записывается
в массив результатов. Поэтому индексы получаются по возрастанию.

Временный массив имеет длину n. После поиска Arrays.copyOf
создаёт массив только из найденных индексов.

Индексы выводятся через пробел. Если совпадений нет,
выводится пустая строка.

Пусть n — количество элементов, k — количество совпадений.

Поиск выполняет n итераций, копирование результата — O(k).
Поскольку k <= n, время метода поиска — O(n).

Ввод занимает O(n), формирование и вывод результата — O(k).
Общее время программы — O(n).

Дополнительная память метода — O(n) для временного массива
и результата. Общая память программы — O(n).

## Задача 8. Фильтрация по знаку

### Идея решения

Создаются временные массивы положительных и отрицательных чисел.
Исходный массив просматривается слева направо.
Каждый ненулевой элемент добавляется в соответствующую группу
Нули пропускаются, исходный порядок внутри групп сохраняется.

После обработки создаются копии заполненных частей массивов.
Положительные элементы выводятся в первой строке,
отрицательные — во второй.
Для пустой группы выводится пустая строка.

### Анализ сложности

Пусть n — длина массива, p — количество положительных элементов,
m — количество отрицательных элементов.

Просмотр массива занимает O(n).
Копирование результатов и вывод занимают O(p + m).
Поскольку p + m <= n, общее время — O(n).

Дополнительная память метода — O(n).
Память всей программы также — O(n).

### Проверки

Автоматические тесты: 6/6 пройдено.
Проверены смешанные знаки, сохранение порядка, исключение нулей,
только положительные, только отрицательные и только нулевые элементы.
Проверен вывод групп и пустых строк.

Пример ручной проверки:
ввод — размер 6, массив 4 -2 0 7 -9 0,
ожидаемая первая строка — 4 7,

## Задача 11. Ближайший к среднему

### Идея решения

Вычисляется сумма элементов S.
Для каждого элемента a сравнивается величина |n * a - S|.

Это расстояние до среднего S / n, умноженное на n.
Такое сравнение позволяет не округлять дробное среднее.

Результат обновляется только при строго меньшем расстоянии.
При равенстве сохраняется первый по индексу элемент.

Сумма и промежуточные вычисления выполняются в long.
При заданном ограничении n < 100000 и элементах типа int,
промежуточные значения помещаются в long.

### Анализ сложности

Подсчёт суммы занимает n итераций.
Выбор ближайшего элемента — n - 1 итераций.

Время метода — O(n), дополнительная память — O(1).
Время всей программы — O(n), память с входным массивом — O(n).

### Проверки

Автоматические тесты: 7/7 успешно пройдено.
Проверены дробное среднее, равные расстояния, точное совпадение
со средним, отрицательные и одинаковые элементы,
крайние значения типа int.
Дополнительно проверены ввод и вывод программы.

## Задача 12. Пара с заданной суммой

### Идея решения

Массив просматривается справа налево.
HashMap хранит для каждого просмотренного значения.
наименьший его индекс справа от текущей позиции.

Для текущего элемента a ищется дополнение targetSum - a.
Если оно найдено, сохраняются индексы пары.

Проверка выполняется до добавления текущего элемента в таблицу,
поэтому один элемент не используется дважды и выполняется i < j.

При движении влево новая найденная пара имеет меньший i.
Для одинакового i таблица обеспечивает наименьший j.

Если пары нет, возвращается массив {-1, -1}.
Вычисления суммы и дополнения выполняются в long.

### Анализ сложности

Выполняются n итераций с поиском и добавлением в HashMap.

При ожидаемом постоянном времени операций хеш-таблицы
ожидаемое время метода — O(n).
Эта оценка не является безусловной гарантией для худшего случая:
коллизии могут увеличивать стоимость операций.

HashMap хранит не более n различных значений.
Дополнительная память метода — O(n).
Ожидаемое время всей программы — O(n), память — O(n).

### Проверки

Автоматические тесты: 8/8 успешно пройдено.
Проверены выбор наименьшего первого индекса,
выбор наименьшего второго индекса при одинаковом первом,
одинаковые значения на разных позициях, запрет повторного
использования одного элемента, отрицательные числа и нулевая сумма.

Отдельно проверено отсутствие ложного совпадения
из-за переполнения int.
Проверен вывод найденной пары и ответа -1 -1.

Пример ручной проверки:
